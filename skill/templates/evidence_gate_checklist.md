# 证据门控清单（每个阶段复制一份）

## A. 路径与范围

- [ ] 已显式切换/设置工作目录；输出解析后的绝对路径。
- [ ] 主工程 XPR、CRC/子工程根、当前构建 XPR 三者分别核对存在。
- [ ] 当前构建由单一指针文件（如 `migration/current.json`）解析，且解析路径仍在允许根内。
- [ ] 受保护主工程 RTL/BD/IP/XDC/XPR 未被写入；保护文件哈希前后一致。
- [ ] 未回退旧工程、未重新初始化副本、未按同名 XPR/修改时间选工程。

## B. 输入与工具

- [ ] 记录本阶段实际使用的源码、固件、IP 配置、约束、脚本、测试数据哈希。
- [ ] 记录工具版本（Vivado/GCC/Python）和安装路径；不把安装路径当工程目录。
- [ ] 输入变化时列出差异；受影响的前序门槛已重跑并保留旧记录。

## C. 执行与日志

- [ ] 记录实际 argv、workdir、起止时间、退出码。
- [ ] 保留 stdout/stderr 双流和完整日志；不只保存摘要。
- [ ] 检查终止标记/日志关键字；不因退出 0 就判定测试执行。
- [ ] 失败、超时、0 字节 Tcl、缺文件、IP 锁定等原始记录保留。
- [ ] 没有把仿真/虚拟目标标成上板。

## D. 结果与判定

- [ ] 正常功能、预期错误注入、检查器负对照分开记录。
- [ ] golden 由独立参考产生；没有由 DUT 反推或改写正确期望。
- [ ] 性能口径写清起止；主要加速比包含配置/搬运/轮询/结果读取。
- [ ] 短输入低于 1×、失败 case、周期差异全部保留；没有选最快轮。
- [ ] 资源对照披露控制变体差异；报告全 SoC 净差，不冒充纯加速器面积。
- [ ] 未测功耗/未复现官方测试/未上板的部分明确写未完成。

## E. 交付与验收

- [ ] `report.md`、`result.json`、`inputs.json`、`logs_index.json` 齐全。
- [ ] `result.json` 标记执行自检状态与独立验收状态；不自行把独立验收改为 PASS。
- [ ] 更新进度文件；旧 PASS 保留原输入范围。
- [ ] 重算命令/入口可在本目录复现。
- [ ] 完成本阶段后停止；不自动进入下一阶段；不发布、不代交赛事系统。
