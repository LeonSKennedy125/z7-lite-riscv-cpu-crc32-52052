# 本轮大模型协作记录摘要

范围：本轮用户请求与当前实际工具反馈，不是项目历次聊天的完整导出。完整提示与原始回答应由参赛者从聊天界面另行导出，按比赛设计报告归档。

| 用户要求/观察 | Agent行动与依据 | 纠错或边界 |
| --- | --- | --- |
| 控制已打开的Vivado | 检查AMD扩展、MCP进程与协议；发现服务运行但无session | 明确“能连接服务”不等于已控制当前窗口 |
| 用户在Tcl Console开启webserver | 通过vivado_connect连接既有GUI；固定只读查询得到工程、器件和顶层 | 不另起工程，不修改项目 |
| 必须先分析后创建Skill | 先读AGENTS/设计说明、XPR/BD/RTL、原TB/脚本、报告和指南，再输出阶段分析 | 由代码确认六级结构，不按5pipeline名称或M译码推断架构 |
| 原入口可能覆盖历史证据 | 检查run_current/R1/CRC rebuild-release调用关系与旧工具路径 | 新脚本复制输入；重构建默认仅计划，实际执行需确认耗时 |
| 不能虚构测试或资源 | 对617项输入做hash核对；提取原始rpt；在Icarus/XSim执行模块测试 | 新模块仿真、历史trace复核、历史时序分别标注 |
| 终端首次解析XCI失败 | 观察2026.1的XCI实际为JSON实例格式，改按真实格式读取参数 | 不依据扩展名强行假定XML，不改原XCI |
| 历史mixed运行目录第一次指定错误 | 脚本拒绝缺失输入；重新枚举真实目录后选择存在的证据 | 不生成假输入补齐，不把错误请求记作通过 |
| 输出必须能被陌生队伍使用 | 参数化根目录/工具位置、新输出拒绝覆盖、增加示例来源和负对照 | 当前未完成跨机器/跨板迁移，不作泛化成功承诺 |

主要可复用判断：检查主BD接入；严格判定TB汇总；分离旁路有效和架构提交；两拍BRAM与暂停中的双源保留；维护源码绑定；保留未约束IO和板级证据缺口。最终实际验证结果、日志位置及文件哈希由 `evidence/validation.json` 和相邻证据文件提供。
